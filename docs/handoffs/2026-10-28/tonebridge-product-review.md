# ToneBridge 기록·학습 경험 검토

검토일: 2026-10-27 (Asia/Seoul)

## 판단

제품의 중심을 **“말하거나 적으면 개인 기록으로 남고, 앱이 정리하고, 다음 학습까지 연결하는 개인 학습장”**에 두는 것이 적합하다. 친구와 커뮤니티 첨삭은 저장된 기록에서 필요할 때 꺼내 쓰는 기능으로 연결한다.

현재 개인 스터디·음성 업로드·학습 시도·친구 피드백·커뮤니티 첨삭이라는 재료는 이미 있다. 가장 큰 개선 기회는 기능 추가보다 이 기능들 사이의 끊김과 반복 선택을 없애는 데 있다.

줄일 대상은 제목 짓기, 폴더 선택, 저장 버튼, 다시 입력하기, 복습할 것 찾기다. 사용자가 직접 떠올리고 말해보는 학습 행동은 짧고 쉽게 남겨둔다.

## 검토 범위와 한계

- 저장소의 Next.js 화면·훅·상태·PWA, Flutter 화면·모델·저장 흐름, Spring 학습·첨삭 서비스·DTO·설정 확인.
- LLM-Wiki의 ToneBridge 학습 기능과 ‘항상 살아있는 연습장’ ADR 확인.
- 운영 웹의 랜딩, 비로그인 커뮤니티, 로그인 화면을 브라우저로 확인.
- 로그인 후 화면은 소스 흐름을 기준으로 분석했다. 실제 계정의 기록·음성·알림 도착·마이크 동작은 실측하지 않았다.
- 사용량 분석이나 사용자 인터뷰가 없으므로 효과와 우선순위는 제품 가설이다. 운영 환경의 AI/FCM 활성 여부도 이번 검토에서 확인하지 않았다.
- 제품 코드와 운영 데이터는 변경하지 않았다. 테스트 실행을 통한 결함 재현을 주장하지 않는다.

## 이미 갖춘 기반

- 로그인 후 스터디 우선 진입, 개인 연습장 자동 생성·재사용.
- 계속 기록을 쌓는 연습장 모델. 세션 종료 절차를 다시 도입할 필요가 없다.
- 텍스트·음성의 개인/친구/커뮤니티 저장 경로와 다중 음성 파일.
- 모바일의 음성 카드 시트 자동 녹음 시작과 카드 검색·정렬.
- 첨삭 결과 저장 시 교정문과 설명을 미리 채우는 기능.
- 저장소 직접 업로드, 인증 복원, 전역 저장 실패 토스트 등 기반 기능.

이 기반을 재사용하면서 웹·모바일의 행동과 데이터 의미를 맞추는 편이 좋다.

| P1 | 작성 텍스트·메모와 웹 녹음이 화면 메모리에 머무름. 검토한 입력 경로에 지속 초안·재전송 큐가 없음 | 새로고침·앱 이탈·네트워크 실패 뒤 사용자가 복구를 책임짐 | 로컬 초안, 서버 동기화, 녹음 종료 후 원본 보관, 재시도 큐 | E5 |

| P1 | 결과 저장 시 첫 세션을 기본 선택. 개인 세션이 없으면 다른 화면에서 생성하도록 유도 | 첫 카드 저장이 중단되고, 첫 세션이 친구 공간일 때 공유 범위를 놓치기 쉬움 | 개인 기본 공간을 서버에서 보장하고 바로 저장. 공유는 별도 명시 액션 | E6 |
| P2 | ‘오늘 할 일’은 친구 요청 수+세션 수 | 복습을 끝내도 숫자가 줄지 않음. 지금 공부할 것을 알려주지 못함 | 실제 미확인 피드백·복습 예정 항목·중단한 연습 집계 | E3 |
| P2 | 카드·시도 모델에 복습 일정과 사용자별 학습 상태가 없음 | 사용자가 목록을 보고 공부할 카드를 직접 찾아야 함 | 사용자별 다음 복습 시각·마지막 결과·최근 학습 위치 도입 | E7 |
| P2 | 웹·모바일의 첨삭 SSE 구독은 결과 화면에 있음. 검토한 웹 서비스 워커에는 push 수신이 없고 모바일 의존성에도 메시징 클라이언트가 없음 | 화면을 닫아도 피드백이 도착한다고 기대하기 어려워 직접 돌아와 확인하게 됨 | 서버에 읽음 상태가 있는 받은함을 만들고 앱 전체에서 갱신. 백그라운드 알림은 별도 구현·기기 검증 | E12 |
| P2 | 연습 점수는 1~5지만 웹 목록 색상은 60/80 기준 | 5점도 낮은 점수 색으로 표시 | 같은 척도와 의미로 통일. 사람 평가와 자동 추정도 구분 | E8 |
| P2 | 모바일 카드 상태는 구형 단일 `nativeAudioUrl` 유무를 먼저 확인 | v2 다중 녹음만 있는 카드가 ‘오디오 없음’으로 분류될 여지 | 서버 응답에 실제 녹음 존재/개수와 내 학습 상태를 명시 | E9 |
| P2 | 운영 다크 모드 로그인 버튼이 밝은 배경+흰 글자로 보임 | 주요 행동의 라벨을 읽기 어려움 | 버튼 전용 배경·전경 색상 토큰 사용. 녹음/저장 CTA도 같은 조합 점검 | E10 |
| P2 | 자동 첨삭은 설정상 기본 비활성, 활성 시에도 48시간 뒤 텍스트 기반 fallback. 실패 시 원문을 돌려주면서 AI 검토 문구를 붙이는 경로가 있음 | 즉각적인 자동 학습으로 보기 어렵고 처리 여부를 오해할 수 있음. 음성 분석도 이 경로로 보장되지 않음 | 정리 작업과 첨삭 분리, 처리 상태·실제 처리자·실패 표시. 음성은 별도 전사/분석 경로 필요 | E11 |

추가로 웹 요청 화면의 카드 목록 무효화 키는 `['cards', sessionId]`, 목록 화면 조회 키는 `['sessions', sessionId, 'cards']`로 다르다. 자동 저장을 강화하기 전에 키를 공유해 저장 직후 화면 반영이 일관되도록 해야 한다(E4, E7).

## 목표 유스케이스

### 1. 길에서 떠오른 문장을 말로 남기기

사용자는 홈의 마이크를 눌러 말하고 정지한다. 원본은 개인 기록에 먼저 저장된다. 제목·언어·날짜·전사는 백그라운드에서 채운다. 저장 실패 시 원본은 남고 ‘기기에 보관됨·동기화 대기’로 표시한다.

목표: 마이크 시작과 정지 외 저장용 추가 탭 0회. 최초 권한 허용은 별도다. 녹음 종료 시점에 원본을 먼저 보관하고, 긴 녹음의 중간 저장은 그다음 단계로 검토한다.

### 2. 공부하다 모르는 표현을 붙여 넣기

어느 화면에서든 빠른 기록을 열어 붙여 넣으면 개인 수집함에 초안으로 저장한다. 제목·태그·학습장을 먼저 묻지 않는다. 붙여 넣은 내용과 사용자가 입력한 내용은 보존하고 자동 요약은 별도 필드에 둔다.

다른 앱의 공유 메뉴로 텍스트·링크·파일을 가져오는 기능은 후속 후보다. PWA의 공유 대상 등록은 설치가 필요하고 플랫폼 지원을 확인해야 하므로, 붙여넣기·파일 가져오기를 기본 대안으로 둔다. [Chrome 공식 문서](https://developer.chrome.com/docs/capabilities/web-apis/web-share-target)

### 3. 원어민 첨삭을 받은 뒤 공부하기

첨삭이 도착하면 원문 기록에 자동 연결한다. 연결 자체는 수동 저장을 요구하지 않는다. ‘학습에 추가’를 한 번 누르면 개인함에 문장·원문·설명·음성·출처가 함께 들어간다. 개인함은 필요하면 자동 생성한다.

자동 카드 생성을 선택한 사용자에게는 중복을 제거한 핵심 표현만 제한적으로 추가한다. 복수 첨삭은 전부 독립 카드로 쌓지 않고 원문 아래 대안으로 유지하며, 현재 학습에 쓸 교정안을 구분한다. 삭제·수정된 첨삭은 저장 시점 사본과 최신 출처 상태를 구분한다.

### 4. 다음날 3분 공부하기

홈에서 ‘3분 복습’을 누르면 앱이 오늘의 카드를 고른다. 상황·뜻을 보고 한 번 떠올리거나 말한 뒤 답을 확인한다. 사용자는 ‘다시 / 괜찮음 / 쉬움’ 중 하나만 표시할 수 있고 나머지 기록과 다음 일정은 자동화한다.

처음에는 단순한 복습 규칙으로 시작한다. 예를 들어 1·3·7일은 초기 실험값으로 두고 실제 회상 결과에 따라 조정한다. 재생·화면 열람만으로 숙달을 확정하지 않는다. 조작을 줄이면서 회상 행동은 유지하는 제안은 [회상 연습 연구 안내](https://www.retrievalpractice.org/summary)와도 방향이 맞지만, ToneBridge에서의 효과는 따로 검증해야 한다.

### 5. 특정 기록을 친구나 커뮤니티에 묻기

기록 상세에서 ‘피드백 받기’를 선택하면 현재 문장과 선택한 녹음이 미리 붙는다. 학습 언어를 기본값으로 제안하고 세부 방언·목표는 접어서 둔다. 친구/공개 범위와 크레딧 비용을 확인한 뒤 전송한다. 원본 개인 기록은 유지한다.

공유 기록을 따로 재입력하지 않고 원본과 요청의 연결을 남긴다. 친구가 답하면 해당 기록에서 확인하고, 필요하면 바로 연습한다. 조작을 줄이더라도 공개 게시·친구 전송·크레딧 사용은 명확한 사용자의 행동으로 남긴다.

### 6. 이동 중 연결이 끊기거나 앱을 닫기

원본 기록과 미전송 작업을 로컬에 남기고 앱 복귀·네트워크 복구 시 동기화한다. 중복 요청 식별자로 카드와 크레딧의 중복 처리를 막는다. 로그인이 만료되면 보관 후 재로그인을 안내하고 다시 이어간다. 앱이 닫혀 있는 동안 모든 브라우저가 계속 동작한다고 가정하지 않는다.

브라우저 저장소에는 용량과 삭제 정책이 있으므로 로컬 저장과 서버 저장을 서로 다른 상태로 표시한다. 로컬 저장을 영구 보관으로 표현하지 않는다. [MDN 저장소 정책](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria)

## 화면 구성 제안

### 스터디 홈

가장 위에 입력창과 마이크가 있는 빠른 기록 영역을 둔다. 그 아래 ‘이어서 3분 공부’, 최근 기록, 새로 도착한 피드백 순서로 배치한다. 친구 초대·세션 만들기·커뮤니티 요청은 관련 맥락에서 노출한다.

예시 배치:

```text
오늘 어떤 표현을 남길까요?
[ 짧게 쓰거나 붙여넣기…           🎙 ]
기기에 저장됨 · 동기화 중

이어서 3분 공부하기       오늘 복습 4개
[ 시작하기 ]

최근 기록
회의에서 하고 싶었던 말   영어 · 어제
카페에서 들은 표현        일본어 · 오늘

새 피드백 1개
어제 남긴 문장의 자연스러운 표현이 도착했어요
```

기존 `/study`와 하단 탭은 먼저 유지해도 된다. 정보 구조 전체를 바꾸기 전에 각 버튼이 약속한 입력과 학습을 바로 시작하게 만드는 편이 효과를 확인하기 쉽다.

### 기록 상세

원문·내 녹음·교정안·다시 연습하기를 하나의 연속된 흐름으로 보여준다. 공통 메모와 개인 메모의 공개 범위를 라벨로 구분한다. 제목·태그·이동·정렬·삭제는 보조 메뉴로 옮기고 기본 화면은 학습 행동에 집중한다.

저장 상태는 ‘기기 저장 / 서버 동기화 / 정리 중 / 완료 / 재시도 필요’로 나누며, 닫아도 안전한지 알려준다. 녹음 미지원·권한 거부·조회 실패·빈 목록은 서로 다른 상태로 표현한다.

### 첫 사용과 랜딩

현재 랜딩은 교정 교환과 크레딧을 앞세우지만 로그인 후에는 스터디가 중심이다. ‘내 표현을 바로 기록하고 다시 공부한다’를 먼저 설명하고 실제 첫 기록으로 연결한다. 모국어·학습 언어 정도를 먼저 받고 닉네임·능숙한 언어·세부 방언은 실제 필요 시점으로 미룰 수 있다.

비로그인 커뮤니티에서 로그인 안내 아래 ‘내 언어 능력으로 교정할 요청이 없다’고 표시되는 것은 실제 판정 전의 부정확한 빈 상태다. 체험 예시 또는 로그인 안내로 일관되게 보여주는 편이 낫다.

## 자동화의 우선순위와 경계

| 동작 | 권장 기본 동작 |
|---|---|
| 개인 초안·내 연습 녹음 보관 | 자동 |
| 제목·언어·태그 제안 | 자동, 쉽게 수정·제거 |
| 클라우드 전사·AI 정리 | 처리 대상·서비스를 설명하고 활성화한 설정에 따라 실행 |
| 받은 첨삭의 원문 연결 | 자동 |
| 첨삭을 복습 카드로 만들기 | 먼저 한 번 저장, 이후 선택 설정으로 제한적 자동 생성 |
| 복습할 항목 선정·다음 일정·학습 기록 | 자동 |
| 친구 전송·공개 게시·크레딧 차감 | 대상·범위·비용이 보이는 명시적 실행 |
| 자동 생성물 | 원본과 구분, 되돌리기·복구 제공 |

음성 인식 결과가 좋다고 발음까지 정확하다고 판단해서는 안 된다. 전사는 내용 복구에 활용하고 발음 피드백은 근거·추정 범위를 별도로 표시한다. 항상 켜진 녹음이나 주변 대화 자동 수집은 첫 구현 범위로 제안하지 않는다.

## 구현 시 필요한 최소 구조

1. **원본 기록**: 텍스트·원본 음성·출처·작성자·공개 범위를 가진 기록. AI 전사·제목·요약은 원본과 별도로 보관한다.
2. **학습 항목**: 원본의 특정 표현·첨삭·음성 구간을 참조한다. 반복 저장을 막는 원본/첨삭 식별자가 필요하다.
3. **개인별 복습 상태**: 카드 작성자와 별개로 학습자, 마지막 학습, 다음 복습, 결과를 관리한다. 공동 카드도 사용자마다 진도가 다르다.
4. **저장·처리 상태**: 사용자별 로컬 초안과 동기화 대기 작업, 서버 처리 작업을 분리한다. 실패 시 원본은 남는다.
5. **범위 변경**: 개인함의 원본을 친구방으로 자동 이동시키기보다 공유 링크/허용된 사본과 출처를 관리한다. 학습 이력이 있는 카드 이동 제한과도 충돌하지 않도록 설계한다.

기존 카드와 세션을 당장 전면 교체할 필요는 없다. 우선 저장 안정성과 자기 카드 연습을 해결하고 원본 연결·개인별 복습 상태를 점진적으로 추가한다.

## 권장 진행 순서

| 단계 | 범위 | 완료 판단 |
|---|---|---|
| 1. 현재 동작 정합성 | 자기 카드 연습, 액션 의도 전달, 공유 기본값, 점수 척도, 다크 모드 버튼, 캐시 키 | 내 카드 연습 가능. 커뮤니티 진입 의도 유지. 개인 저장이 친구방으로 기본 선택되지 않음 |
| 2. 안심하고 바로 기록 | 빠른 입력, 녹음 종료 후 원본 저장, 지속 초안, 저장 상태, 재시도·중복 방지 | 새로고침·일시적 연결 끊김·재로그인 후에도 초안을 이어서 저장 가능 |
| 3. 자동 정리와 첨삭 연결 | 선택한 전사, 자동 제목·언어, 출처 연결, 음성 보존, 중복 저장 방지 | 한 번 저장한 첨삭이 원문·음성과 연결되고 처리 실패가 기록 손실로 이어지지 않음 |
| 4. 매일 이어지는 학습 | 사용자별 복습 상태, 3분 루틴, 실제 할 일 집계, 이어하기 | 사용자가 학습장과 카드를 고르지 않아도 복습을 시작하고 중단 지점으로 복귀 가능 |
| 5. 유입 경로 확대 | 모바일 공유 받기, PWA 공유 대상, 파일·스크린샷 입력 | 지원 기기에서 가져온 콘텐츠가 개인함에 안정적으로 저장됨 |

1~2단계는 AI 없이도 진행할 수 있다. 이 단계에서 기록 완료율과 재방문이 좋아지는지 확인한 뒤 AI 작업량과 비용을 늘리는 편이 합리적이다.

## 검증과 지표

현재 수치는 측정하지 않았다. 아래는 목표 후보이며 출시 전 기준선을 먼저 수집한다.

- 개인 글 기록: 저장 버튼 추가 탭 0회. 음성 기록: 최초 권한을 제외하고 시작·정지 후 저장 확인 가능.
- 기록 시작→서버 저장 완료 전환율과 중간 이탈률.
- 화면 이탈·새로고침·네트워크 끊김·401·업로드/confirm 실패 후 초안 복구 성공률.
- 중복 카드·중복 요청·중복 크레딧 차감 발생률.
- 첨삭 수신→학습 추가→첫 복습 전환율과 7일 후 회상 결과.
- 자동 제목·언어·카드의 수정/삭제 비율. 자동 카드가 많아질수록 유용하다고 보지 않는다.
- 알림 열람률보다 알림 이후 실제 복습 완료율, 알림 해제율.
- 웹·Flutter에서 같은 유스케이스와 공개 범위가 유지되는지 확인.

자동 저장은 빠르게 타이핑한 뒤 다른 응답이 도착하는 경우, 여러 기기가 같은 메모를 고치는 경우도 확인해야 한다. 수정 버전과 충돌 복구 없이 마지막 응답으로 덮어쓰면 사용자가 더 자주 확인하게 된다.
