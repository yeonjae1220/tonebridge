# 이메일 비밀번호 재설정

- 로그인 → 비밀번호를 잊으셨나요? → 메일 요청 → 15분 일회용 링크 → 새 비밀번호 저장 → 재로그인.
- 이메일/비밀번호로 가입한 LOCAL 계정만 대상. Google 계정은 Google 로그인 유지.
- 요청 응답은 계정 존재·제공자·이메일 제한과 무관하게 빈 202. 조회/발송은 별도 유한 큐에서 처리한다.
- 토큰은 256비트 난수. DB에는 SHA-256 해시만 저장하며 링크의 fragment로 전달한다.
  페이지가 읽은 뒤 주소에서 제거하고, 토큰은 메모리에만 보관한다. 새로고침했다면 원본 메일 링크를 다시 연다.
- 사용된 토큰·같은 계정의 다른 링크는 재사용할 수 없다. 사용자 행 잠금으로 동시 재설정/로그인/refresh를 직렬화한다.
- 비밀번호 변경과 credentials_version 증가는 같은 DB 트랜잭션이다. access/refresh JWT의 버전이 다르면 거부한다.
  기존 버전 없는 JWT는 0으로 해석하므로 재설정하지 않은 기존 회원의 세션은 유지된다.
- 현재 모든 기기의 로그인 알림 스트림도 커밋 후 종료한다. 이미 실행 중인 요청까지 되돌리지는 않는다.
- Redis가 실패하면 재설정 요청 제한은 fail-closed. 기본 요청 IP 10회/15분, 이메일 3회/시간,
  확인 IP 20회/15분, 실제 메일 100통/일. IP 확인 불가 시 공유 unknown 버킷을 적용한다.
- 비밀번호는 기존 ASCII 조합 규칙을 유지하고, BCrypt 한계에 맞춰 8~72자로 가입과 재설정을 통일한다.
- 만료 토큰은 매시간 삭제하며 회원 삭제 시 FK cascade로 정리한다. 원문 비밀번호/토큰/메일 주소는 오류 로그에 남기지 않는다.

## 운영 메일 설정

SMTP는 기본 비활성이다. Kubernetes `tonebridge/tonebridge-mail` Secret의 다음 키를 backend 환경변수로 읽는다.
표의 값은 운영값 자체가 아니라 설정 지침이다. 비밀번호를 명령 인자·저장소·채팅·로그에 적지 않는다.

| 키 | 용도 |
|---|---|
| PASSWORD_RESET_ENABLED | `true`일 때 요청·확인 활성화 |
| MAIL_HOST | SMTP 호스트 |
| MAIL_PORT | STARTTLS 제출 포트, 기본 587 |
| MAIL_USERNAME | 발송 계정 |
| MAIL_PASSWORD | 발송 계정의 앱 비밀번호 |
| MAIL_FROM | 발송 가능한 이메일 주소, 표시 이름은 ToneBridge |

`FRONTEND_URL`은 신뢰하는 HTTPS 서비스 URL이어야 한다. 요청 Host 헤더를 링크 생성에 사용하지 않는다.
SMTP 인증·필수 STARTTLS·서버 인증서 검증·유한 연결/읽기/쓰기 제한 시간을 사용한다.
backend의 공인 IP TCP 587 egress만 추가하고 기존 사설·CGNAT·링크로컬 차단을 유지한다.

기존 홈랩 발송 계정의 SMTP 인증을 확인했다. 같은 계정을 사용하는 서비스와 발송 한도를 공유한다.
운영 비밀은 새 `tonebridge-mail` Secret으로 분리하며 기존 서비스 Secret을 수정하지 않는다.
이 Secret은 CI가 생성하는 `tonebridge-secret`과 별개이므로 재배포 때 사라지지 않는다.
회전 시 이 Secret을 변경하고 backend를 다시 롤아웃한다. 장기적으로 전용 발송 계정을 사용할 수 있다.

## 배포와 복구

1. SMTP Secret을 `PASSWORD_RESET_ENABLED=false`로 준비한다.
2. V29(사용자 credentials_version + 토큰 테이블)를 포함한 backend → frontend 배포를 완료한다.
3. 새 이미지와 마이그레이션, SMTP 연결 및 공개 상태 API의 비활성을 확인한다.
4. Secret의 활성화 키만 true로 바꾸고 backend를 롤아웃한다. `/api/auth/password-reset/status`가 true인지 확인한다.

메일 장애 시 활성화 키를 false로 설정하고 backend를 롤아웃하면 기능을 닫을 수 있다.
선택 기능인 SMTP의 외부 장애가 학습 서비스 헬스를 실패시키지 않도록 mail health indicator는 비활성이다.
SMTP 장애는 계정 존재를 드러내지 않도록 요청 응답과 분리하고 서버에 실패 유형만 기록한다.
원문 링크는 재로그인/업데이트 과정에서 자동 사용되지 않으며 GET 요청으로 소비하지 않는다.

주의: 비밀번호 재설정이 사용된 뒤에는 credentials_version 검사가 없는 구버전 backend로 단순 롤백하지 않는다.
구버전은 취소된 access JWT를 다시 허용할 수 있다. 복구는 새 검증을 유지한 수정 배포를 우선한다.

## 검증 범위

PostgreSQL 실제 마이그레이션과 보안 필터, Redis 실제 Lua 제한, SMTP 메시지/설정 단위 검증,
브라우저 데스크톱/모바일의 요청·확인·만료·장애·입력 유지·주소 토큰 제거를 포함한다.
운영 계정 비밀번호는 검증용으로 변경하지 않는다. 사용자가 허용한 SMTP 확인 메일은 1통만 보냈고 서버 접수를 확인했다.
받은편지함 도착/스팸 분류는 수신자 확인이 필요하다.

PR #42 배포 검증: 백엔드 전체 196건, 브라우저 전체 244건(재설정 8건 포함), Flutter 89건 통과.
운영 V29 적용, SMTP STARTTLS 인증, 기능 활성화, 두 Deployment Ready 1/1과 공개 API/화면을 확인했다.
운영 전 live manifest diff: 기존 설정 삭제 없음. 선택 SMTP Secret 참조와 backend의 공인 IP 587 egress만 추가.

2026-11-14 후속: 상태 조회 15초·제출 30초 제한 시간을 추가했다. 상태 재시도는 문서 전체를
새로고침하지 않으므로 fragment에서 제거한 메모리 토큰과 입력을 보존한다. 요청이 취소되거나
시간 초과해도 서버 처리 취소/실패를 보장하지 않으므로 자동으로 POST를 재전송하지 않는다.
성공 응답을 잃었다면 받은편지함 또는 새 비밀번호 로그인을 확인하고 필요한 경우 새 링크를 요청한다.
