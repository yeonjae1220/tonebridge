# 파일럿 수집·보관 정책

기준일: 2026-10-29 · 안내문 버전: `pilot-v1-2026-10-29`
범위: 친구 중심 모바일 웹 MVP, 친구 5쌍·2주 검증. 구현 완료와 운영 활성화는 별도다.
운영 책임: ToneBridge 운영자. 연락 경로: 서비스 `/help` 또는 모집 때 사용한 기존 채널.

## 수집 조건

- 전역 `TONEBRIDGE_VALIDATION_ENABLED` 기본값과 배포 매니페스트는 false다.
- 운영자가 안내문을 제공하고 참여 의사를 확인한 계정만 `validation_participants`에 등록한다.
  브라우저는 등록·동의 여부·사용자 UUID를 임의로 지정할 수 없으며 등록용 공개 API도 없다.
- 참여 행의 잠금을 모두 확보한 뒤 새 DB 조회 시각을 기준으로 시작 시각 이상, 종료 시각 미만이고 철회되지 않은 등록만 유효하다. 잠금 대기 중 만료된 요청은 수집하지 않는다. 1회 등록 기간은 최대 30일이고,
  이번 파일럿은 14일로 설정한다. 등록 중복은 오류이며 묵시적 연장·자동 재등록은 하지 않는다.
- 친구 수락은 두 계정 모두 참여 중이어야 한다. 공유 연습장의 활동은 작성자뿐 아니라
  현재 연습장 구성원 모두 참여 중이어야 한다. 개인 연습장은 본인의 참여 등록으로 충분하다.
  따라서 참가자의 개인 연습 활동도 저장될 수 있지만 친구 쌍 지표의 첫 반복에는 포함되지 않는다.
- 진단은 인증 토큰의 계정이 참여 중일 때만 저장한다. 비참여/비활성 상태에는 정상 204로 무시한다.
  진단 요청 자체는 기존 클라이언트가 계속 전송할 수 있어 일반 접근 로그 정책은 별도로 적용된다.
- 참여하지 않거나 철회해도 무료 학습·친구 관계·기존 학습 콘텐츠 이용에는 영향이 없다.
  이 파일럿 참여는 학습 콘텐츠 열람·공개·AI 학습에 대한 포괄적 동의가 아니다.

## 데이터 목록과 목적

| 저장 위치 | 수집 항목 | 이용 목적 | 보관·삭제 |
| --- | --- | --- | --- |
| PostgreSQL `validation_participants` | 사용자 UUID, 안내문 버전, 참여 의사 확인·시작·종료·철회·등록 시각 | 수집 허용 여부 검증 | 종료 또는 철회 중 빠른 시각부터 30일 경과 후 일별 정리. 정상 운영 시 그 시점부터 최대 31일. 계정 삭제 시 FK 삭제 |
| PostgreSQL `learning_activity` | 이벤트 4종, 사용자·상대·연습장·카드·시도 UUID, 서버 발생 시각 | 연결, 첫 반복, 피드백 후 재시도, 2주차 활동 | 30일 경과 행을 매일 삭제. 정상 운영 시 최대 31일. 철회 처리 시 연결된 활동도 삭제 |
| PostgreSQL `validation_diagnostic_daily` | UTC 날짜, 진단 7종, 횟수 | 녹음·업로드 오류 추이 | 매일 오늘과 이전 29개 UTC 날짜만 유지. 정리 실행 간격 포함 최대 31일 이내. 사용자별 제거 불가 |
| 모집·관찰 대장(저장소 밖, 운영자 전용) | 참여자 코드, 초대한 쌍 수, 안내 확인, 기기/브라우저, 도움 여부, 중단 이유, 문의 처리 상태 | 미가입 분모와 정성 평가 | 파일럿 종료 후 30일 안에 연락처/UUID 대응표·개별 관찰 기록 삭제. 집계 요약만 보존 |
| 기존 서비스 DB·MinIO | 계정, 언어, 친구/연습장 관계, 문장, 메모, 음성, 피드백 | 서비스 제공 | 파일럿 만료로 학습 콘텐츠가 삭제되지는 않음. 원본 삭제/공유 접근 중단은 본인·범위 확인 후 별도 처리 |
| 운영 로그·문의·백업 | 아래 별도 항목 | 장애 대응, 문의 처리, 복구 | 검증 테이블의 31일 정책으로 포괄하지 않음 |

내부 UUID와 작은 모집단의 집계도 접근을 제한한다. 이벤트에는 문장·음성·파일경로·이메일·IP·토큰을
복사하지 않는다. 진단 테이블에는 사용자·세션·URL·원시 요청을 저장하지 않는다.
운영자는 통상 집계 숫자만 조회하며, 원시 UUID 조회는 수집 검증·철회 처리에 한정한다.
모집 명단, SQL 인자, 결과의 개인별 상세를 Git·PR·CI 로그·공개 위키에 올리지 않는다.

## 지표의 해석 범위

- 학습 이벤트: FRIEND_ACCEPTED, EXAMPLE_SAVED, PRACTICE_SAVED, FEEDBACK_SAVED.
  EXAMPLE_SAVED는 예시 **음성 저장**이다. 텍스트 카드 생성·재생 완료를 의미하지 않는다.
- 진단: RECORDING_ATTEMPT, RECORDING_SUCCEEDED, RECORDING_FAILED, MICROPHONE_DENIED,
  UPLOAD_ATTEMPT, UPLOAD_SUCCEEDED, UPLOAD_FAILED. UPLOAD는 저장소 PUT 단계다.
- 진단은 클라이언트의 best-effort 보고다. 종료·통신 실패·중복·조작으로 수가 달라질 수 있다.
  재시도 전송이나 사용자별 이벤트 추적은 하지 않는다. 시도-성공 차이를 전부 장애로 단정하지 않는다.
- 진단 API는 프로세스당 분당 600회까지 저장한다. 비참여자는 한도를 소비하지 않는다.
  다중 복제본에서는 합산 한도가 증가한다. 비용 산정이나 과금의 근거가 아니다.
- 영속 집계는 PostgreSQL 일별 UPSERT가 정본이다. Micrometer 카운터는 보조 수치이며 재시작 시 초기화된다.
  Prometheus 연결은 이 구현의 선행 조건이 아니다. 기존 monitoring 설정을 변경하지 않았다.
- 일별 진단은 참여자 전체 합계로, 특정 친구 쌍·기기·시간대별로 분해할 수 없다.
  자정 기준 부분 날짜는 다른 리허설/파일럿 활동과 섞일 수 있어 별도 날짜에 실행하는 편이 좋다.
- [학습 보고서](../../scripts/validation/report.sql)의 재시도는 학습자 단위다.
  초대 클릭·재생·화면 이탈·자발적 재사용 이유는 자동 수집하지 않고 관찰 기록으로 보완한다.

## 철회, 삭제, 장애 및 복원

- `/help` 또는 모집 채널로 철회를 요청한다. 운영자는 로그인 계정/알려진 모집 경로로 본인을 확인한다.
  단순 문의에 기입된 이메일·닉네임만으로 권한을 바꾸지 않는다.
- [withdraw.sql](../../scripts/validation/withdraw.sql)은 등록을 철회하고 actor/peer 또는 현재 공유
  연습장으로 연결된 활동을 같은 트랜잭션에서 삭제한다. 공유 활동 삭제로 상대방 지표도 줄 수 있다.
  친구 관계와 학습 콘텐츠는 바꾸지 않는다. 이미 구성원에서 제거된 과거 연습장 등 추가 대상이
  있으면 원본 기록의 관계를 확인해 별도 검토한다.
- 수집 트랜잭션이 참여 행을 공유 잠금으로 보유하므로 철회는 먼저 시작한 저장 완료를 기다린 뒤 삭제한다.
  철회 커밋 이후 시작하는 수집은 차단된다. 요청을 보낸 시점과 운영 처리 완료 시점은 다를 수 있다.
- 사용자별 연결이 없는 일별 진단 집계는 한 사람의 기여분만 찾아 제거할 수 없다. 기간 만료로 삭제한다.
- 정리 작업은 수집 플래그가 false여도 동작한다. 서버 기동 60초 후 시작하고 이후 완료부터 24시간 간격이다.
  서버/DB 중단 시 만료 시각을 보장할 수 없다. 복구 후 정리 성공과 잔존 최소 시각을 확인한다.
- 백업 복원 시 수집을 끈 채 복원하고, 별도 운영 기록에 남긴 철회/삭제 요청을 재적용한 뒤
  만료 정리를 실행·검증한다. 백업에 남은 옛 참여 등록으로 수집을 재개하지 않는다.

## 운영 로그·문의·백업의 별도 관리

2026-10-29 조사 당시 Prometheus는 30일 보관, Loki 설정은 기간 기반 자동 삭제가 비활성이다.
현재 운영 로그에는 요청 경로·응답 상태·처리 시간과 일부 UUID가 포함되며, 인증 제한 Redis 키는
이메일/IP를 사용할 수 있다. 일부 오류 로그도 식별자를 포함할 수 있다. 로그 전체를 익명이라고 안내하지 않는다.
문의는 본문·선택 이메일·앱 버전·User-Agent를 lab 문의 서비스로 전달한다.

외부 모집 시작 전 다음을 확인해 이 문서와 안내문에 실제 적용값을 반영한다.

| 대상 | 운영 기준/해야 할 일 | 현재 확인 수준 |
| --- | --- | --- |
| ToneBridge 접근·오류 로그 | 보관 30일을 목표로 ToneBridge 범위의 삭제 설정·마스킹 검토. 공용 Loki의 다른 서비스 정책을 임의로 변경하지 않음 | 자동 삭제 미적용. 실제 만료 확인 필요 |
| 문의 본문·연락처 | 해결 후 30일 내 운영자 삭제를 기준으로 저장 서비스의 삭제 기능과 담당자 확인 | 보관/삭제 경로 검증 필요 |
| DB·음성 백업 | 기존 스케줄의 실제 원격 보관 기간, NAS 스냅샷·별도 사본·MinIO 포함 여부 확인. 복원 후 철회 재적용 | DB 덤프 존재는 기존 문서로 확인. 전체 만료 기간은 미확정 |
| 모집 대응표·관찰 기록 | 운영자만 접근, 파일럿 종료 후 30일 내 삭제 | 운영 대장 생성 시 적용 |

이 미확정 항목이 남아 있는 동안 “모든 개인정보가 31일 후 영구 삭제”라고 고지하거나 외부 모집을 시작하지 않는다.
실제 정책 검증 없이 법적 준수 여부를 단정하지 않는다.
